## iOS — supported, generated on macOS

| | |
|---|---|
| Framework | Capacitor iOS **8.5.3** (`@capacitor/ios`) |
| Configuration | `capacitor.config.ts` → `ios` block |
| Project | **Not committed.** Generated by `npx cap add ios` |
| Build workflow | `.github/workflows/build-genei-ios.yml` (macOS 15 runner) |
| Status | **Configured and CI-buildable. No `.ipa` produced here.** |

### Why the Xcode project is not in this repository

`npx cap add ios` generates `ios/App/App.xcodeproj` from Capacitor's own template. A
`project.pbxproj` maintained by hand drifts from what Capacitor expects, is close to
unreviewable in a diff, and breaks on every Capacitor upgrade. Generating it on a machine
that can is correct by construction; committing it is not.

### Why no `.ipa` is delivered

**Apple requires macOS and Xcode to build any iOS application.** Neither exists in the
Linux environment this project was developed in, and no macOS toolchain can be installed
there. This is a platform requirement, not a code gap.

The macOS workflow builds for the **simulator**, which needs no Apple Developer account and
no signing identity, and therefore proves the app compiles and links against the iOS SDK.
A device `.ipa` additionally requires:

| Requirement | Why |
|---|---|
| Apple Developer Program membership | $99/year — a purchase, not a technical step |
| A signing certificate + provisioning profile | Issued by Apple to a paid account |
| A registered device UDID (for ad-hoc) | Or App Store distribution |

### To produce an `.ipa`

On a Mac with Xcode:

```sh
pnpm install && pnpm build
npx cap add ios && npx cap sync ios
cd ios/App && pod install
open App.xcworkspace    # set your signing team, then Product > Archive
```

Or run the workflow with `build_ipa: true` once signing secrets are configured.

## What remains unverified, and exactly why

| Item | Missing requirement |
|---|---|
| An installable Android APK | JDK + Android SDK + Gradle in the environment, or a successful Android CI run |
| Android runtime behaviour (permissions, WebView, startup, navigation, storage) | An emulator or a physical device |
| A signed Windows release | A CA-issued code-signing certificate (`WINDOWS_SIGNING_CERT_BASE64`) |
| A verified Windows *execution* | A Windows machine to run the installer on |
| iOS | Not a supported target |

## Installation

**Windows (portable):** extract the zip and run `GeneiAI.exe`. No installation, no admin
rights. Windows may show a SmartScreen warning because the build is unsigned — see below.

**Windows (installer):** run `Genei-AI-Desktop-Setup-<version>.exe`.

**Android:** not deliverable from this environment. On a machine with the Android SDK:
`pnpm install && pnpm android:build`, which syncs the web assets and runs
`gradlew assembleRelease`. The output is `android/app/build/outputs/apk/release/`.

**Web/PWA:** `pnpm install && pnpm build && pnpm start`.

## The SmartScreen warning is expected

The Windows artifacts are **unsigned** because no code-signing certificate is configured.
A self-signed certificate only removes the warning on machines that already trust it, so it
is not a substitute for a CA-issued one. This is stated rather than papered over: the
build is real, the signature is absent, and those are different claims.
