# Genei AI Windows EXE Download and Build Guide

## What is provided

The repository now contains a reproducible Windows build workflow for **GeneiRunner.exe**, the paired BYOH workstation runner. The executable is generated from `ai_director/genei_runner.spec` and includes the secure runner installer entry point and Python dependencies required for workstation pairing.

The current development environment is Linux, so it cannot produce a genuine Windows PE executable here. The repository therefore includes two truthful build paths: a local Windows PowerShell/batch build and a GitHub Actions Windows artifact build. A binary must be generated by one of these Windows builders before it can be offered as a download.

## Local Windows build

From a Windows checkout of this repository, run:

```powershell
.\packaging\build_windows_exe.ps1
```

Or double-click `packaging/build_windows_exe.bat`. The script creates a local virtual environment, installs the AI Director requirements and PyInstaller, builds the executable, verifies that `GeneiRunner.exe --help` runs, and writes `dist/GeneiRunner.exe.sha256`.

The generated artifact is:

```text
dist/GeneiRunner.exe
dist/GeneiRunner.exe.sha256
```

To pair the runner after downloading it, use the one-time token from **API Integrations → BYOH Workstation**:

```powershell
.\dist\GeneiRunner.exe --server-url https://genieai-tc7qfq5i.manus.space --token genei_<one-time-token>
```

## GitHub Actions download

The workflow `.github/workflows/build-genei-runner-windows.yml` runs on `windows-latest` when manually dispatched or when the runner source changes. It builds and validates the binary, then uploads `GeneiRunner-windows-x64` containing the EXE and checksum. Open the completed workflow run in GitHub and download the artifact from the **Artifacts** section.

## Security and release policy

Do not distribute a binary without checking its SHA-256 checksum and reviewing the source commit. Production distribution should additionally sign the EXE with the project’s Windows code-signing certificate. The runner never receives provider API keys; it uses a short-lived pairing token and receives only approved job contracts.

The Manus project checkpoint is the downloadable source/configuration deliverable. It is not itself a Windows EXE. Publishing a direct EXE URL requires a completed Windows build and a release artifact upload.
